Before you start

Five minutes of context so every lab makes sense.

What is MCP, in one paragraph

The Model Context Protocol (MCP) is an open standard — think of it as a USB-C port for AI. It lets Claude plug into external tools and data (like ThousandEyes or Meraki) through a standard interface. You ask Claude a question in plain English; Claude decides which tools to call, calls them, and weaves the results into its answer. You never touch an API or write a script.

Two ways to run Claude — pick based on which labs you're doing

  • Claude Desktop app (recommended) — handles everything: the ThousandEyes OAuth connector plus the local Meraki and Splunk servers (a browser can't reach those). If you're doing more than ThousandEyes today, use Desktop so it's all in one place.
  • Claude in your browser (claude.ai) — fine if you're only doing the ThousandEyes labs. Nothing to install; add the connector and sign in.

Connect ThousandEyes (OAuth — browser or Desktop)

The ThousandEyes MCP server is cloud-hosted by Cisco, so you connect to it directly as a custom connector — no install, no config files.

⭐
Browser or Desktop — your choice, same steps. You can add this OAuth connector in Claude in your browser (claude.ai) or the Claude Desktop app. Desktop is preferred for today: the Meraki and Splunk labs run local servers that only Claude Desktop can reach, so doing ThousandEyes in Desktop too keeps everything in one place — no app switching.
  1. Open Claude and go to Connectors
    In Claude (claude.ai in your browser, or the Claude Desktop app), open Settings → Connectors.
  2. Add a custom connector
    Click Add custom connector.
  3. Enter the name and URL
    Name: ThousandEyes MCP Server  ·  Remote MCP server URL:
    https://api.thousandeyes.com/mcp
    Click Add.
  4. Sign in when the browser window opens
    A window opens asking you to sign in with your ThousandEyes credentials (use the demo account from the proctor if you don't have your own) and to agree to share your token with Claude.
  5. Turn on the tools
    Back in Claude, click Configure on the ThousandEyes connector and switch on auto-allow so tools run without prompting each time. Tools come in two groups — Read-only and Write/delete. Enable Write/delete too, because Lab 1 creates real tests.

Verify it's connected

What ThousandEyes MCP tools are available to you? List them all.

You should see tools like list_alerts, get_anomalies, create_synthetic_test, search_outages and many more. If Claude says it has no tools, re-check the sign-in step and that the connector is enabled.

ℹ️
A single custom connector works on a free Claude account. Your org must not be opted out of ThousandEyes AI features, and your sign-in must have the API Access permission (the demo accounts already do).

Meraki Magic MCP

A local MCP server that talks to your Meraki Dashboard. Hands-on for anyone with a Meraki API key; everyone else follows the live demo.
🖥️
Meraki Magic runs on your laptop, so it needs the Claude Desktop app (a browser can't reach a local server). You'll also need Python 3.8+, Git, and a Meraki Dashboard API key + Org ID. No key today? Follow the demo and complete this later.

Set up Meraki Magic (one-time, ~10 minutes)

  1. Clone the repository
    git clone https://github.com/CiscoDevNet/meraki-magic-mcp-community.git
cd meraki-magic-mcp-community
  2. Create & activate a Python virtual environment
    # macOS
python3 -m venv .venv
source .venv/bin/activate

# Windows
python -m venv .venv
.venv\Scripts\activate
    Your prompt now shows (.venv). Re-run the activate line each time you open a new terminal.
  3. Install dependencies
    pip install -r requirements.txt
  4. Create your credentials file
    # macOS  cp .env-example .env  &&  open -e .env
# Windows  copy .env-example .env   (then open .env in Notepad)
    Fill in — no quotes, no spaces around =:
    MERAKI_API_KEY=your_actual_api_key_here
MERAKI_ORG_ID=your_actual_org_id_here
ENABLE_CACHING=true
CACHE_TTL_SECONDS=300
READ_ONLY_MODE=false
  5. Add it to Claude Desktop's config
    Open claude_desktop_config.json — Windows: %APPDATA%\Claude · macOS: ~/Library/Application Support/Claude/. Add the Meraki block inside "mcpServers" (use your real path to fastmcp):
    "Meraki_Magic_MCP": {
  "command": "/full/path/to/meraki-magic-mcp-community/.venv/bin/fastmcp",
  "args": ["run","-t","stdio",
           "/full/path/to/meraki-magic-mcp-community/meraki-mcp-dynamic.py"],
  "env": {
    "MERAKI_API_KEY": "your_key",
    "MERAKI_ORG_ID": "your_org_id",
    "READ_ONLY_MODE": "false"
  }
}
    On Windows the command path ends in \.venv\Scripts\fastmcp.exe — use forward slashes or double back-slashes.
  6. Restart Claude Desktop and verify
    What MCP servers and tools are available to you right now?
    You should see the Meraki Magic tools listed.

MCP Tool-Building — Build Your Own MCP Server Featured

Go beyond using MCP servers — build one. Use Cursor's AI to scaffold a working MCP server with little or no coding, then connect it to Cursor, Claude Desktop or Claude Code.
🎯
Lab outcome. By the end you'll have a working stdio MCP server, connected in Cursor → Settings → MCP (green status), and you can ask the AI in plain English to call your tools — list alerts, check utilisation, query an API. You do not need to write TypeScript by hand if you follow the Cursor path.

Choose your path

Path A — Cursor Agent Recommended

Little coding knowledge required. You describe what you want; Cursor's AI creates files, runs terminal commands, and fixes errors. You copy prompts, paste your API docs link, and approve changes.

Path B — Manual coding

For developers who want to understand every line. Follow Labs 1–4 below, then connect Cursor or Claude using the same mcp.json pattern.

What you'll build

┌──────────────────┐ stdin/stdout ┌──────────────────────┐ │ Cursor Chat │ ◄────────────────────► │ Your MCP Server │ │ Claude Desktop │ JSON-RPC (MCP) │ (node dist/index.js)│ │ or Claude Code │ └──────────┬───────────┘ └──────────────────┘ │ HTTPS ▼ ┌──────────────────────┐ │ External API / Data │ │ (REST, DB, files…) │ └──────────────────────┘

Your MCP server exposes Tools (actions the model can invoke — the focus of this lab), and optionally Resources (read-only data by URI) and Prompts (reusable templates). For Cursor and Claude on your laptop, servers use stdio transport: the client spawns your process and talks over stdin/stdout — no HTTP port required.

Prerequisites

  • Cursor installed — cursor.com
  • Node.js 18+ — ask Cursor: "Check if Node 18+ is installed; if not, tell me how to install it on my OS."
  • API credentials for the system you're integrating (a token — keep it private)
  • A link to the API documentation (paste it into Cursor chat)
  • Optional: Claude Desktop or Claude Code if you also want to drive the server from Claude
ℹ️
You don't need to know TypeScript, JSON-RPC, or MCP internals. In Agent mode, Cursor runs the terminal commands for you.

Path B — Manual coding (optional, for developers)

LAB 1 Scaffold the project
Create the folder and install the MCP SDK.
mkdir my-mcp-server && cd my-mcp-server
npm init -y
npm install @modelcontextprotocol/sdk zod
npm install -D typescript @types/node

tsconfig.json

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "Node16",
    "moduleResolution": "Node16",
    "outDir": "dist",
    "rootDir": "src",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*"]
}

package.json — set "type": "module" and scripts

{
  "type": "module",
  "main": "dist/index.js",
  "scripts": {
    "build": "tsc",
    "start": "node dist/index.js"
  },
  "engines": { "node": ">=18" }
}

src/index.ts — minimal server skeleton

#!/usr/bin/env node
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from "@modelcontextprotocol/sdk/types.js";

const server = new Server(
  { name: "my-mcp-server", version: "1.0.0" },
  { capabilities: { tools: {} } }
);

server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [
    {
      name: "hello",
      description: "Returns a greeting. Use to verify MCP is working.",
      inputSchema: {
        type: "object",
        properties: { name: { type: "string", description: "Name to greet" } },
        required: ["name"],
      },
    },
  ],
}));

server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === "hello") {
    const name = String(request.params.arguments?.name ?? "world");
    return { content: [{ type: "text", text: `Hello, ${name}! MCP server is running.` }] };
  }
  return { content: [{ type: "text", text: `Unknown tool: ${request.params.name}` }], isError: true };
});

const transport = new StdioServerTransport();
await server.connect(transport);

Build

npm run build   # produces dist/index.js
LAB 2 Add real tools
Each tool needs a name, a description (the model reads this to decide when to call it), and an inputSchema.
  • Use clear, prefixed names: te_list_alerts, sf_get_account
  • Descriptions should say when to use the tool, not just what it does
  • Return JSON as formatted text in content: [{ type: "text", text: "…" }]
  • On failure, set isError: true with a helpful message
  • Never log secrets; use console.error for diagnostics (stdout is for MCP only)

Register a second tool in ListTools

{
  name: "list_items",
  description: "List items from the API. Use when the user asks to see records or inventory.",
  inputSchema: {
    type: "object",
    properties: { limit: { type: "number", description: "Max items (default 10)" } },
  },
}

Handle it in CallTool

if (request.params.name === "list_items") {
  const limit = Number(request.params.arguments?.limit ?? 10);
  const data = await apiGet("/items?limit=" + limit);
  return { content: [{ type: "text", text: JSON.stringify(data, null, 2) }] };
}
LAB 3 API client & authentication
Create src/client.ts to isolate HTTP calls from the MCP handlers.
const BASE = process.env.MY_API_BASE_URL ?? "https://api.example.com/v1";
const TOKEN = process.env.MY_API_TOKEN;

export async function apiGet(path: string) {
  if (!TOKEN) throw new Error("MY_API_TOKEN is not set");
  const res = await fetch(`${BASE}${path}`, {
    headers: { Authorization: `Bearer ${TOKEN}`, Accept: "application/json" },
  });
  if (!res.ok) {
    const body = await res.text();
    throw new Error(`API ${res.status}: ${body.slice(0, 200)}`);
  }
  return res.json();
}
🔒
Store tokens in environment variables only. Never commit them to git or paste them into chat. Use a dedicated env-var name per service.

Security

  • Secrets: environment variables or OS keychain — never in source code
  • Least privilege: scope API tokens to the minimum permissions
  • Write tools: require confirmation for destructive actions
  • Output: redact PII and secrets from tool responses
  • Config files: chmod 600 on configs and wrapper scripts; keep them out of git

Troubleshooting & glossary

Claude says it has no tools

Re-open Settings → Connectors and confirm the connector is enabled. For ThousandEyes, re-run the browser sign-in. For Meraki/Splunk, fully quit and reopen Claude Desktop and check your config paths.

ThousandEyes connector won't sign in

Confirm your account has API Access permission and your org isn't opted out of AI features. Demo accounts from the proctor already satisfy both.

Meraki server won't start

Check the fastmcp path in your config is the full absolute path, the .venv was activated when you ran pip install, and your .env has no quotes or stray spaces.
