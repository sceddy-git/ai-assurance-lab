Before you start

Five minutes of context so every lab makes sense.

What is MCP, in one paragraph

The Model Context Protocol (MCP) is an open standard — think of it as a USB-C port for AI. It lets Claude plug into external tools and data (like ThousandEyes or Meraki) through a standard interface. You ask Claude a question in plain English; Claude decides which tools to call, calls them, and weaves the results into its answer. You never touch an API or write a script.

Everything runs in one place — this web app

  • No installs, no config files, no Claude Desktop. You're already in the lab platform. The chat on the right talks to Claude on AWS Bedrock, which calls ThousandEyes and Meraki through their official hosted MCP servers on your behalf.
  • One-time setup per service: open ⚙️ Credentials in the header, paste in your ThousandEyes OAuth Bearer token and Meraki API token, and click Test Connection. That's it — no OAuth pop-ups to click through, no local Python servers, no JSON config to edit.
  • Once a service shows Connected ✓, just ask Claude questions in the chat — it automatically knows which tools it has available and uses them for you.

ThousandEyes MCP

Connect this web app to Cisco's official ThousandEyes MCP server — one OAuth Bearer token, pasted once, no install.
🎟️
No ThousandEyes account? See the lab proctor — demo licenses and an OAuth Bearer token are provided for today.

Connect ThousandEyes (2 minutes, in this app)

The ThousandEyes MCP server is cloud-hosted by Cisco. This lab platform talks to it on your behalf using your own personal OAuth Bearer token — nothing to install, nothing to configure locally.

  1. Get your ThousandEyes OAuth Bearer token
    In the ThousandEyes UI, go to Account Settings → Users and Roles → User API Tokens (or ask your proctor for the demo account's token). Copy the OAuth Bearer Token — you'll paste it once.
  2. Open Credentials in this app
    Click ⚙️ Credentials in the header of the chat page.
  3. Paste your token and save
    Paste the token into the ThousandEyes field (labeled OAuth Bearer Token) and click Save Token.
  4. Test the connection
    Click Test Connection. You should see Connected ✓ — that's it, you're done. The header status dot next to "ThousandEyes" will also turn green.

Verify it's connected

What ThousandEyes MCP tools are available to you? List them all.

You should see tools like list_alerts, get_anomalies, create_synthetic_test, search_outages and many more. If Claude says it has no tools, go back to Credentials and re-check the token and Test Connection result.

ℹ️
Your token is encrypted before it's stored and is never shown back to you or exposed to the browser in plaintext. Your sign-in must have the ThousandEyes API Access permission (the demo accounts already do).

ThousandEyes Labs

LAB 1 ★ Prospect Demo — from a domain to a customer-ready report
The flagship sales-engineering workflow. ~15–20 minutes, start to finish.

Step 1 — Discover the prospect's internet services

Open servicefinder.thousandeyesresearch.com, search the prospect's primary domain (a real prospect, or a well-known brand), and take a screenshot of the results. Pick 5–10 meaningful URLs — homepage, login, API, CDN.

Step 2 — Ask Claude to create the tests

In Claude, attach your screenshot, then send:

Here is a screenshot of ServiceFinder results for a prospect called [PROSPECT]. Please create a ThousandEyes page load test for each of these URLs: [paste 5–10 URLs, one per line] For each test: 1. Label it with the prefix "[PROSPECT] — " (e.g. "Acme — Homepage") 2. Assign it to our closest available Enterprise Agent 3. Use a 5-minute interval 4. Confirm each test's name and ID once created

Step 3 — Pull the results (after ~5 minutes)

The tests for [PROSPECT] should have their first results now. Retrieve the latest metrics for every test you created. For each URL show: page load time, HTTP response code, pass/fail, any errors, and which agent ran it. Summarise as a table.

Step 4 — Generate the customer report ★

Using those results, write a professional customer-facing performance report for [PROSPECT] with: 1) Executive summary, 2) Test coverage table, 3) Key findings, 4) What this means for their business, 5) How ThousandEyes solves it, 6) Recommended next steps (a 30-day trial). Tone: trusted advisor, reference real numbers, not too technical. Audience: a Network Manager / IT Director.
Push it further
Turn this report into an email I can send to the IT Director — under 200 words, with a subject line referencing the specific issue you found.
Based on what we found, which additional ThousandEyes test types would you recommend, and what business question does each answer for this prospect?

Which enterprise agents are reporting packet loss greater than 1% to the affected target right now? Show me the path-visualisation summary.

Prove or disprove a reported slowdown with data.
Show me uptime and time-to-first-byte for the Customer Portal HTTP test over the last 24 hours. Call out any drops below our 99.5% SLA.

Surface hidden problems before users notice.

Meraki MCP

Connect this web app to Cisco's official Meraki MCP server — one API key, pasted once, no install.
🎟️
You'll need a Meraki Dashboard API key and your Organization ID. No key today? See the proctor for a demo key, or follow along with the live demo.

Connect Meraki (2 minutes, in this app)

The Meraki MCP server is cloud-hosted by Cisco. This lab platform talks to it on your behalf using your own personal API key — nothing to install, nothing to configure locally, no Claude Desktop needed.

  1. Get your Meraki API key and Organization ID
    In the Meraki Dashboard, go to Organization → Settings → Dashboard API access and generate an API key (or ask your proctor for the demo key). Your Organization ID is the numeric value in the dashboard URL, or ask your proctor.
  2. Open Credentials in this app
    Click ⚙️ Credentials in the header of the chat page.
  3. Paste your key and Organization ID, then save
    Paste the key into the Meraki field, paste your Organization ID into the field below it, and click Save Token. Almost every Meraki tool call needs the Organization ID — saving it here means Claude will use it automatically instead of asking you for it in every message.
  4. Test the connection
    Click Test Connection. You should see Connected ✓ — that's it, you're done. The header status dot next to "Meraki" will also turn green.

Verify it's connected

What Meraki MCP tools are available to you? List them all.

If Claude says it has no Meraki tools, go back to Credentials and re-check the key and Test Connection result. If Claude asks you for an Organization ID when running a lab prompt, go back to Credentials and make sure it's saved in the Meraki card.

Splunk MCP Optional

Investigate your Splunk data in plain English — no SPL required.
🖥️
Unlike ThousandEyes and Meraki, there's no single Cisco-hosted Splunk MCP server — the server has to run somewhere that can talk to a Splunk instance (port 8089), and that "somewhere" is different for each student: your own laptop, a shared facilitator-hosted server, etc. So instead of a fixed connector, this app lets you plug in your own MCP server URL.

Connect Splunk (in this app)

Ask your facilitator whether they're providing a shared Splunk MCP server URL for today, or whether you're expected to run your own locally (in which case you'll need a tunnel like ngrok so this web app — running in the cloud — can reach a server on your laptop).

  1. Get your MCP server URL (and credentials, if running your own)
    Either the URL your facilitator gives you, or — if running locally — start your local Splunk MCP server, expose it with a tunnel (e.g. ngrok http 8000), and use the public https://…ngrok.io/mcp URL it gives you. Your facilitator will also give you the Splunk host/port 8089 and credentials your local server itself needs to reach Splunk (that part is configured on the server, not in this app).
  2. Open Credentials in this app
    Click ⚙️ Credentials in the header, then find the Splunk card.
  3. Paste the MCP Server URL
    Paste the URL into the MCP Server URL field. If your server also enforces its own auth token/API key, paste that into Auth Token / API Key too — otherwise leave it blank.
  4. Save and test
    Click Save, then Test Connection. You should see Connected ✓. A "Splunk" status dot will also appear in the chat header once configured.
LAB 1 Natural-language threat hunt
Investigate suspicious activity without writing SPL.
Search Splunk for failed login attempts (Windows Event ID 4625) in the last 2 hours. Show the top 10 source IPs by failure count and flag any with more than 50 — likely brute force.
For the top offending IP, check for any successful logins in the last 24 hours. If so, which accounts and from which endpoints?
Write an optimised SPL saved search that alerts when more than 20 failed logins come from the same IP within 5 minutes, and suggest an alert action.
LAB 2 Operational health & index audit
Know what data you have and whether it's still flowing.
List all Splunk indexes and tell me which haven't received events in the last 60 minutes. Flag these as potentially broken pipelines.
What's the current indexer disk usage? Are any indexers above 85% capacity?
Show event volume by index for the last 24 hours, sorted descending. Highlight any index down more than 50% vs the same window yesterday.
LAB 3 Network event correlation
Join Meraki syslog & ThousandEyes data already in Splunk.
Search the Meraki syslog index for 802.11 disassociation events in the last 4 hours. Correlate the timestamps with ThousandEyes latency spikes in the network_performance index — are they happening simultaneously?
Build a timeline starting from the first Meraki disassociation event, then show network performance over the next 15 minutes. Which event was likely causal?
Write an SPL search that joins these two sources on timestamp within a 5-minute window and produces a correlation table I can save as a dashboard panel.
Appendix

Troubleshooting & glossary

Claude says it has no tools

Open ⚙️ Credentials and check the status for that service. If it doesn't say Connected ✓, re-paste the token/key and click Test Connection again. Then start a new chat message — tool availability is refreshed per request.

ThousandEyes won't connect

Confirm your account has API Access permission and your org isn't opted out of AI features. Demo accounts from the proctor already satisfy both. Double-check you copied the full token with no extra spaces.

Meraki won't connect

Confirm the API key is correct and that your Meraki Organization ID matches an org that key has access to. Re-paste both in ⚙️ Credentials and click Test Connection.

Splunk won't connect (bonus module)

Confirm the MCP Server URL is reachable from the internet (this app runs in the cloud, so localhost URLs won't work — you need a tunnel like ngrok, or the facilitator's shared URL). If your server enforces an auth token, make sure it's entered in ⚙️ Credentials too. If you're running your own local server, check its own Splunk host/port/credentials configuration separately — that's set up on the server side, not in this app.

Quick glossary

  • MCP — Model Context Protocol; the standard that lets Claude use external tools.
  • Connector — how you add an MCP server to Claude (remote URL + OAuth, or a local command).
  • Enterprise Agent — a ThousandEyes vantage point that runs your tests.
  • Org ID / API key — your Meraki Dashboard credentials, entered once in ⚙️ Credentials.
